CRUD with Fetch API

CRUD operations are the backbone of any application. Whether it is Instagram, Amazon, or your MERN project, everything revolves around creating, reading, updating, and deleting data from a server.

1. Understanding CRUD Internally

CRUD operations interact with the server and database. Each operation maps to an HTTP method.

Operation HTTP Method Database Action
CreatePOSTINSERT
ReadGETSELECT
UpdatePUT / PATCHUPDATE
DeleteDELETEDELETE
Frontend (Fetch) → API → Backend → Database → Response → UI

2. POST (Create)

POST sends data to the server. The data is included in the request body. 

fetch("https://api.com/posts", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    title: "Hello",
    body: "Post content"
  })
})

How it Works Internally

  • Browser sends HTTP request
  • Body is converted to JSON string
  • Server parses JSON
  • Data is stored in database
  • Response (201 Created) is returned
Always use JSON.stringify() because server cannot understand JS objects directly.

3. GET (Read)

GET requests retrieve data. No body is sent. 

fetch("https://api.com/posts")

Internal Flow

  • Request sent
  • Server queries database
  • Returns JSON response
GET requests are cached by browsers for performance.

4. PUT vs PATCH

PUT (Full Update)

Replaces entire resource. 

{
  "name": "New Name"
}

If original object had more fields, they may be lost.

PATCH (Partial Update)

Updates only specific fields. 

{
  "name": "Updated Name"
}
Use PATCH when updating small changes. Use PUT when replacing entire data.

5. DELETE (Remove)

fetch("https://api.com/posts/1", {
  method: "DELETE"
})

Internal Flow

  • Request sent to server
  • Server deletes record
  • Response (200 or 204) returned

6. Headers

Headers provide metadata about the request.

Important Headers

  • Content-Type → defines data format
  • Authorization → security token
  • Accept → expected response format
headers: {
  "Content-Type": "application/json"
}
Without correct headers, server may not understand your request.

7. Authorization Header (Security)

Used to authenticate users using tokens (JWT). 

headers: {
  "Authorization": "Bearer TOKEN"
}

Flow

  • User logs in
  • Server returns token
  • Token stored in frontend
  • Token sent in every request
Never expose tokens publicly (security risk).

8. Status Codes

HTTP Status Codes are responses sent by the server to indicate what happened to a request. They help the client (browser/frontend) understand whether the request was successful or not.

Range Meaning Explanation
2xx Success The request was successful and processed correctly.
3xx Redirection Further action is needed (like redirecting to another URL).
4xx Client Error The request has an error from the client side (wrong input, missing data).
5xx Server Error The server failed to process a valid request.

Important Status Codes

  • 200 → OK
    Request was successful and data is returned.
    Example: Fetching user details.

  • 201 → Created
    New resource is successfully created.
    Example: User registration or adding a product.

  • 204 → No Content
    Request successful but no data is returned.
    Example: Deleting a record.

  • 400 → Bad Request
    Client sent invalid data.
    Example: Missing fields or wrong input format.

  • 401 → Unauthorized
    User is not authenticated (not logged in or token missing).
    Example: Accessing protected route without JWT.

  • 403 → Forbidden
    User is authenticated but does not have permission.
    Example: Normal user trying to access admin panel.

  • 404 → Not Found
    Requested resource does not exist.
    Example: Invalid API route or wrong ID.

  • 409 → Conflict
    Request conflicts with existing data.
    Example: Email already exists.

  • 422 → Unprocessable Entity
    Valid data format but logical error.
    Example: Weak password or invalid business rule.

  • 500 → Internal Server Error
    Something went wrong on the server.
    Example: Database failure or server crash.

Simple Understanding

Think of status codes like exam results:

  • 2xx → Pass
  • 3xx → Go somewhere else
  • 4xx → Your mistake
  • 5xx → Server mistake

9. Error Handling

async function fetchData(){
  try{
    let res = await fetch("API_URL");

    if(!res.ok){
      throw new Error("HTTP Error: " + res.status);
    }

    let data = await res.json();
    console.log(data);

  }catch(error){
    console.log("Error:", error.message);
  }
}

Types of Errors (with Examples)

  • 1. Network Error → Happens when there is no internet or server is unreachable 
    // Example: Wrong domain / no internet
fetch("https://wrongapiurl.com/data")
  .then(res => res.json())
  .catch(err => console.log("Network Error:", err));

    👉 This error occurs before getting any response from the server.


  • 2. HTTP Error → Server responds but with error status (404, 500) 
    // Example: API returns 404 Not Found
async function getUser(){
  try{
    let res = await fetch("https://jsonplaceholder.typicode.com/invalid-url");

    if(!res.ok){
      throw new Error("HTTP Error: " + res.status);
    }

    let data = await res.json();
  }catch(err){
    console.log(err.message);
  }
}

    👉 Here server responds, but response is not successful.


  • 3. Parsing Error → Happens when JSON is invalid or cannot be parsed 
    // Example: Invalid JSON parsing
try{
  let data = JSON.parse("Invalid JSON");
}catch(err){
  console.log("Parsing Error:", err.message);
}

    👉 Occurs when converting response or data fails.

Important:
  • Always use try-catch with async/await to handle errors properly
  • fetch() does NOT throw error for HTTP errors → we must check res.ok manually
  • Network errors go directly to catch block
  • Parsing errors occur during JSON conversion

10. Best Practices

  • Always check res.ok
  • Use async/await for readability
  • Handle errors properly
  • Use correct HTTP method
  • Secure APIs using Authorization

11. Real World Flow

User Action → Fetch API → Server → Database → Response → UI Update

Example: User clicks "Add Product" → POST request → data stored → UI updates

12. try...catch...finally

Used to handle errors safely in JavaScript. 

try {
  let result = 10 / 2;
  console.log(result);
} catch (error) {
  console.log("Error occurred:", error.message);
} finally {
  console.log("This always runs");
}

Explanation

  • try → Code that may cause error
  • catch → Handles error
  • finally → Always executes (cleanup code)
finally is optional but useful for closing resources, loaders, etc.

13. throw Keyword

Used to create custom errors manually. 

function checkAge(age){
  if(age < 18){
    throw new Error("You must be 18+");
  }
  console.log("Access granted");
}

try{
  checkAge(16);
}catch(err){
  console.log(err.message);
}
throw helps you control validation and error flow manually.

14. JSON (JavaScript Object Notation)

JSON is a format used to send and receive data between frontend and backend.

Convert JS → JSON

let user = { name: "Fathima", age: 21 };

let jsonData = JSON.stringify(user);
console.log(jsonData);

Convert JSON → JS

let data = '{"name":"Fathima","age":21}';

let obj = JSON.parse(data);
console.log(obj.name);
API always sends data in JSON format.

15. LocalStorage & SessionStorage

LocalStorage

  • Stores data permanently (until manually cleared)
  • Shared across tabs
// Save
localStorage.setItem("name", "Fathima");

// Get
let name = localStorage.getItem("name");

// Remove
localStorage.removeItem("name");

// Clear all
localStorage.clear();

SessionStorage

  • Data removed when tab is closed
  • Not shared across tabs
sessionStorage.setItem("user", "Naja");
Feature LocalStorage SessionStorage
Lifetime Permanent Until tab close
Scope All tabs Single tab
Storage only stores strings → use JSON.stringify() for objects.

16. Simple To-Do App using LocalStorage

HTML

    JavaScript

    let tasks = JSON.parse(localStorage.getItem("tasks")) || [];

function renderTasks(){
  let list = document.getElementById("taskList");
  list.innerHTML = "";

  tasks.forEach((task, index) => {
    let li = document.createElement("li");
    li.innerHTML = `
      ${task}
      
    `;
    list.appendChild(li);
  });
}

function addTask(){
  let input = document.getElementById("taskInput");
  if(input.value === "") return;

  tasks.push(input.value);
  localStorage.setItem("tasks", JSON.stringify(tasks));

  input.value = "";
  renderTasks();
}

function deleteTask(index){
  tasks.splice(index, 1);
  localStorage.setItem("tasks", JSON.stringify(tasks));
  renderTasks();
}

renderTasks();

    Flow

    • User adds task
    • Stored in array
    • Saved in localStorage
    • Rendered on UI
    • Persists even after refresh
    This is a basic real-world example of CRUD using browser storage.
