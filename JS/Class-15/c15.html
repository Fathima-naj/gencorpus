API Interaction in JavaScript

1. What is an API?

API stands for Application Programming Interface. It acts as a bridge between frontend (browser) and backend (server).

Real Life Analogy

  • You = Client (Browser)
  • Waiter = API
  • Kitchen = Server

You don't directly access the kitchen. The API communicates and returns data.

APIs allow dynamic data fetching without reloading the page.

2. How API Works

Browser (JS)
   ↓
HTTP Request
   ↓
Server (API)
   ↓
Database Processing
   ↓
JSON Response
   ↓
Browser Displays Data

Key Concepts

  • Request → Sent from client
  • Response → Sent from server
  • JSON → Data format

3. What is JSON?

JSON (JavaScript Object Notation) is a lightweight data format. 

{
  "name": "Fathima",
  "age": 21
}
Most APIs return data in JSON because it is fast and easy to parse.

4. What is Fetch API?

Fetch API is used to send HTTP requests and receive responses. It is promise-based and modern.

Basic Syntax

fetch("API_URL")
.then(res => res.json())
.then(data => console.log(data))
.catch(err => console.log(err));

How Fetch Works Internally

  • Request is sent to server
  • Server processes request
  • Response is returned
  • Fetch returns a Promise
fetch() does not return data directly, it returns a Promise.

5. Why Two .then() ? (Important)

fetch(url)
.then(res => res.json())
.then(data => console.log(data))

Explanation

  • First .then → handles Response object
  • res.json() → converts raw stream into JS object
  • Second .then → gets actual data
res.json() also returns a Promise, that's why we need another .then()

6. async / await Version

async function getData(){
  let res = await fetch("API_URL");
  let data = await res.json();
  console.log(data);
}
getData();

Why async/await?

  • Cleaner syntax
  • Looks synchronous
  • Better readability

7. HTTP Methods

HTTP methods define what type of action the client (browser) wants to perform on the server. They are very important in API communication because they tell the server what to do with the data.

Method Purpose
GETRetrieve data
POSTCreate data
PUTUpdate entire data
PATCHPartial update
DELETERemove data

Detailed Explanation

1. GET (Read Data)

GET is used to fetch data from the server without changing anything. It is the most commonly used HTTP method. 

fetch("https://api.com/users")
  • Safe method (does not modify data)
  • Used for displaying data (users, posts, products)

2. POST (Create Data)

POST is used to send new data to the server and create a resource. 

fetch("https://api.com/users", {
  method: "POST",
  body: JSON.stringify({ name: "Fathima" }),
  headers: {
    "Content-Type": "application/json"
  }
});
  • Used in forms (signup, login, add product)
  • Data is sent in request body

3. PUT (Update Entire Data)

PUT is used to update an entire resource. It replaces the old data completely. 

fetch("https://api.com/users/1", {
  method: "PUT",
  body: JSON.stringify({ name: "New Name" }),
  headers: {
    "Content-Type": "application/json"
  }
});
  • Replaces full object
  • If some fields are missing, they may be removed

4. PATCH (Partial Update)

PATCH is used to update only specific fields of a resource. 

fetch("https://api.com/users/1", {
  method: "PATCH",
  body: JSON.stringify({ name: "Updated Name" }),
  headers: {
    "Content-Type": "application/json"
  }
});
  • Updates only selected fields
  • Safer than PUT when partial changes are needed

5. DELETE (Remove Data)

DELETE is used to remove data from the server. 

fetch("https://api.com/users/1", {
  method: "DELETE"
});
  • Deletes a resource permanently
  • Used in admin panels, dashboards
GET is most commonly used in frontend development, while POST, PUT, PATCH, and DELETE are mainly used when working with backend or full-stack applications.

9. Understanding res.json()

Response from fetch is not directly usable because it is a stream. 

res.json()
  • Converts stream → JavaScript object
  • Returns a Promise
Without res.json(), you cannot access actual API data.

10. Display Data in DOM

HTML

    JavaScript

    fetch("https://jsonplaceholder.typicode.com/users")
.then(res => res.json())
.then(users => {
  let list = document.getElementById("userList");

    let li = document.createElement("li");

    11. Error Handling

    Error handling is important when working with APIs because things can go wrong while fetching data. There are mainly two types of errors:

    • Network Error
    • HTTP Error

    1. Network Error

    A network error happens when the request cannot reach the server at all. This means the browser failed to connect to the API.

    Common Reasons

    • No internet connection
    • Wrong URL (invalid domain)
    • Server is down
    fetch("wrong-url")
.catch(err => console.log("Network Error"));

    In this case, fetch will directly go to .catch().

    Network errors happen before the server responds.

    2. HTTP Error

    An HTTP error happens when the request reaches the server, but the server responds with an error status code.

    Common Status Codes

    • 404 → Not Found
    • 500 → Server Error
    • 403 → Forbidden
    async function getData(){
  let res = await fetch("API_URL");

  if(!res.ok){
    throw new Error("Request Failed");
  }

  let data = await res.json();
}

    Here, we manually check res.ok to detect errors.

    Fetch does NOT throw errors automatically for 404 or 500.

    Key Difference

    Type When it Happens Handled By
    Network Error Request fails before reaching server .catch()
    HTTP Error Server responds with error (404, 500) Manual check (res.ok)

    12. Real World Example

    async function loadPosts(){

let res = await fetch("https://jsonplaceholder.typicode.com/posts");

let posts = await res.json();

let container = document.getElementById("posts");

posts.slice(0,5).forEach(post => {

let div = document.createElement("div");

div.innerHTML = `

    ${post.title}
    

    ${post.body}
    
`;

container.appendChild(div);

});

}
loadPosts();

    Why slice(0,5)?

    • Limit data
    • Improve performance
