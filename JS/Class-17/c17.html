Advanced JavaScript

1. Prototypes

JavaScript uses prototype-based inheritance, which means objects can inherit properties and methods from other objects.

  • Every object in JavaScript has an internal hidden property called [[Prototype]]
  • This links one object to another (parent object)
  • Using this, objects can share methods and properties

🔹 Basic Example

function Person(name){
  this.name = name;
}

Person.prototype.sayHello = function(){
  console.log("Hello " + this.name);
}

let user = new Person("Fathima");
user.sayHello(); // Hello Fathima

Explanation:

  • Person is a constructor function
  • Person.prototype is an object where shared methods are stored
  • All objects created using new Person() will access these methods
  • user does NOT have sayHello directly → it is taken from prototype

🔹 How Prototype Works Internally

console.log(user.__proto__ === Person.prototype); // true
  • __proto__ is a reference to the object's prototype
  • When JS cannot find a property → it searches in prototype (Prototype Chain)

🔹 Prototype Chain

let arr = [1,2,3];

console.log(arr.__proto__);              // Array prototype
console.log(arr.__proto__.__proto__);    // Object prototype
console.log(arr.__proto__.__proto__.__proto__); // null

Flow:

Array → Object → null

This is called Prototype Chain.

🔹 Why Prototype is Important (Memory Efficiency)

❌ Without Prototype (Bad Practice)

function Person(name){
  this.name = name;
  this.sayHello = function(){
    console.log("Hello " + this.name);
  }
}

let u1 = new Person("A");
let u2 = new Person("B");
  • Each object creates a new copy of sayHello()
  • Wastes memory

✅ With Prototype (Best Practice)

function Person(name){
  this.name = name;
}

Person.prototype.sayHello = function(){
  console.log("Hello " + this.name);
}
  • Only ONE copy of sayHello()
  • All objects share it → efficient

🔹 Adding Properties to Prototype

Person.prototype.age = 21;

let user1 = new Person("Fathima");
console.log(user1.age); // 21

Even though age is not inside object → it comes from prototype.

🔹 Overriding Prototype Property

user1.age = 25;

console.log(user1.age); // 25 (own property)

JS first checks object → then prototype.

🔹 Built-in Prototype Example

Array.prototype.myMethod = function(){
  console.log("Custom method");
}

let nums = [1,2,3];
nums.myMethod(); // Custom method

Here we are extending the Array prototype.

🔹 Key Interview Points

  • Prototype is used for inheritance in JavaScript
  • All objects have a hidden [[Prototype]]
  • Functions have a prototype property
  • Prototype helps in memory optimization
  • JS uses Prototype Chain to resolve properties

Key Point: Methods inside prototype are shared → memory efficient.

2. this, call, apply, bind

this

Refers to the object that is executing the function.

let user = {
  name: "Naja",
  greet(){
    console.log(this.name);
  }
}
user.greet();

call()

Calls function with given this and arguments separately.

function greet(city){
  console.log(this.name + " from " + city);
}

greet.call({name:"Fathima"}, "Malappuram");

apply()

Same as call, but arguments passed as array.

greet.apply({name:"Fathima"}, ["Kerala"]);

bind()

Returns a new function with fixed this.

let newFunc = greet.bind({name:"Fathima"});
newFunc("India");

3. Garbage Collection

JavaScript automatically manages memory using a process called Garbage Collection.

It removes objects from memory when they are no longer needed, so developers don’t have to manually free memory.

  • Uses Mark and Sweep algorithm
  • Works based on reachability (references)
  • If an object has no reference → it becomes eligible for deletion

🔹 Basic Example

let user = { name: "A" };

user = null; // now object has no reference

Explanation:

  • Initially, object {name:"A"} is stored in memory
  • user is pointing (referencing) that object
  • After user = null → reference is removed
  • No reference → object becomes eligible for garbage collection

🔹 How Garbage Collection Works (Mark & Sweep)

Step 1: Mark Phase

  • JavaScript starts from root objects (global variables, window, etc.)
  • Marks all reachable (used) objects

Step 2: Sweep Phase

  • Unmarked objects are considered unused
  • They are removed from memory

🔹 Workflow Example

let user = { name: "Fathima" };

let admin = user; // two references

user = null;

Explanation:

  • Object still exists because admin is referencing it
  • Garbage collector will NOT delete it
admin = null;
  • Now no references exist
  • Object becomes eligible for garbage collection

🔹 Nested Object Example

let user = {
  name: "A",
  address: {
    city: "Kochi"
  }
};

user = null;
  • Main object lost reference
  • Nested object also becomes unreachable
  • Both will be removed from memory

🔹 Function Scope Example

function createUser(){
  let user = { name: "Temp User" };
}

createUser();
  • user exists only inside function
  • After function execution → no reference remains
  • Automatically garbage collected

🔹 Important Concept: Reachability

An object is kept in memory as long as it is reachable.

  • Reachable → NOT deleted
  • Unreachable → deleted

🔹 Memory Leak (Important for Interview)

let users = [];

function addUser(){
  let user = { name: "A" };
  users.push(user);
}
  • Objects are always stored in array
  • References are never removed
  • This causes memory leak

Solution:

users = []; // remove references

🔹 Key Interview Points

  • JavaScript uses automatic memory management
  • Uses Mark and Sweep algorithm
  • Works based on references (reachability)
  • No reference → eligible for garbage collection
  • Memory leaks happen when references are not removed

Key Point: JavaScript frees memory automatically when objects are no longer reachable.

4. Map, Set, WeakMap

These are advanced data structures in JavaScript used for storing and managing data efficiently.

🔹 Map

A Map stores key-value pairs just like objects, but with more flexibility.

  • Keys can be any data type (string, number, object, function)
  • Maintains insertion order
  • Has built-in methods for easy operations

Example:

let map = new Map();

map.set("name", "Fathima");
map.set(1, "Number Key");

console.log(map.get("name")); // Fathima
console.log(map.get(1)); // Number Key

Using Object as Key:

let obj = {id: 1};

map.set(obj, "User Data");

console.log(map.get(obj)); // User Data

Important Methods:

  • set(key, value) → add data
  • get(key) → retrieve data
  • has(key) → check existence
  • delete(key) → remove item
  • clear() → remove all items
  • size → number of entries

🔹 Set

A Set stores unique values only (no duplicates allowed).

  • Duplicates are automatically removed
  • Stores values (not key-value pairs)

Example:

let set = new Set([1, 2, 2, 3]);

console.log(set); // {1, 2, 3}

Adding Values:

set.add(4);
set.add(2); // ignored (duplicate)

console.log(set); // {1, 2, 3, 4}

Checking & Deleting:

console.log(set.has(2)); // true

set.delete(2);

console.log(set); // {1, 3, 4}

Use Case:

  • Remove duplicates from array
let numbers = [1,2,2,3,4,4];

let unique = [...new Set(numbers)];

console.log(unique); // [1,2,3,4]

🔹 WeakMap

A WeakMap is similar to Map but has special memory behavior.

  • Keys must be objects only
  • Keys are stored as weak references
  • If object is removed → automatically garbage collected
  • Not iterable (no loop)

Example:

let weakMap = new WeakMap();

let user = {name: "Fathima"};

weakMap.set(user, "User Data");

console.log(weakMap.get(user)); // User Data

Garbage Collection Behavior:

let user = {name: "A"};

weakMap.set(user, "Data");

user = null;
  • No reference to object
  • Garbage collector removes it automatically
  • Prevents memory leaks

🔹 Map vs Object

  • Object keys → only string/symbol
  • Map keys → any data type
  • Map has better performance for frequent operations

🔹 Set vs Array

  • Array → allows duplicates
  • Set → only unique values

🔹 Map vs WeakMap

  • Map → strong reference (not auto deleted)
  • WeakMap → weak reference (auto garbage collected)
  • WeakMap → keys must be objects
  • WeakMap → not iterable

🔹 Key Interview Points

  • Map → flexible key-value storage
  • Set → unique values only
  • WeakMap → avoids memory leaks
  • WeakMap keys must be objects
  • Set is commonly used to remove duplicates

Key Point: Use Map for flexible data storage, Set for unique values, and WeakMap for memory-safe object references.

7. Debouncing

Debouncing is a technique used to delay function execution until a certain time has passed after the last event.

It ensures that a function runs only after the user stops triggering an event (like typing, scrolling, resizing).

🔹 Basic Idea

  • User triggers event multiple times (typing)
  • Function execution is delayed
  • If event happens again → timer resets
  • Function runs only once after delay

🔹 Debounce Function

function debounce(fn, delay){
  let timer;

  return function(...args){
    clearTimeout(timer);

    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  }
}

Explanation:

  • timer stores the timeout ID
  • clearTimeout() cancels previous execution
  • setTimeout() sets new delay
  • Only the last call executes

🔹 Real Example: Search Input (🔥 Important)

function searchData(value){
  console.log("Searching for:", value);
}

const debouncedSearch = debounce(function(e){
  searchData(e.target.value);
}, 500);

document.getElementById("searchBox")
  .addEventListener("input", debouncedSearch);

How it works:

  • User types "F", "Fa", "Fat", "Fathima"
  • Without debounce → function runs 4 times ❌
  • With debounce → runs only once after typing stops ✔️

🔹 Step-by-Step Flow

User types → timer starts (500ms)
User types again → previous timer cleared
New timer starts again
User stops typing → timer completes
Function executes once

🔹 Without Debounce (Problem)

document.getElementById("searchBox")
  .addEventListener("input", function(e){
    console.log("Searching:", e.target.value);
  });
  • Runs on every keystroke ❌
  • Too many API calls ❌
  • Poor performance ❌

🔹 With Debounce (Solution)

  • Reduces unnecessary calls ✔️
  • Improves performance ✔️
  • Better user experience ✔️

🔹 Real-Life Analogy

Imagine a lift door 🚪:
It waits for people to stop entering before closing.
Each new person resets the timer → same as debounce.

🔹 Use Cases

  • Search input (API calls)
  • Window resize events
  • Scroll events
  • Form validation

Key Point: Debouncing ensures a function runs only after the user stops triggering an event.

8. Throttling

Throttling is a technique used to limit how often a function executes within a specific time interval.

It ensures that a function runs at most once in a given time period, no matter how many times the event is triggered.

🔹 Basic Idea

  • Event triggers many times (scroll, resize)
  • Function executes immediately
  • Then it is blocked for a fixed time (limit)
  • After the time passes → allowed again

🔹 Throttle Function

function throttle(fn, limit){
  let flag = true;

  return function(...args){
    if(flag){
      fn.apply(this, args);
      flag = false;

      setTimeout(() => {
        flag = true;
      }, limit);
    }
  }
}

Explanation:

  • flag controls execution
  • First call → function runs immediately
  • Next calls within time → ignored
  • After limit → function allowed again

🔹 Real Example: Scroll Event 

function handleScroll(){
  console.log("Scrolling...");
}

const throttledScroll = throttle(handleScroll, 1000);

window.addEventListener("scroll", throttledScroll);

How it works:

  • User scrolls continuously
  • Without throttle → function runs many times ❌
  • With throttle → runs once every 1 second ✔️

🔹 Step-by-Step Flow

User scrolls → function executes immediately
Next scroll events → ignored for 1 second
After 1 second → next scroll triggers function again

🔹 Without Throttling (Problem)

window.addEventListener("scroll", function(){
  console.log("Scrolling...");
});
  • Runs hundreds of times ❌
  • Performance issues ❌
  • UI lag ❌

🔹 With Throttling (Solution)

  • Limits execution ✔️
  • Improves performance ✔️
  • Better control over events ✔️

🔹 Debounce vs Throttle

  • Debounce → runs after user stops event
  • Throttle → runs at regular intervals

🔹 Real-Life Analogy

Imagine a water tap 🚰:
Throttling controls water flow to come at fixed intervals, not continuously.

🔹 Use Cases

  • Scroll events
  • Window resize
  • Mouse movement tracking
  • Button click rate limiting

Key Point: Throttling ensures a function runs at most once in a fixed time interval.

10. Functional vs Procedural Programming

These are two different programming paradigms (styles) used to write and organize code.

🔹 Functional Programming

Functional programming focuses on writing pure functions and avoiding changes to data.

  • Uses pure functions
  • Avoids modifying existing data (immutability)
  • No side effects
  • Functions are treated as first-class citizens

Example:

function add(a, b){
  return a + b;
}

console.log(add(2, 3)); // 5

Example with Array:

let numbers = [1, 2, 3];

let doubled = numbers.map(num => num * 2);

console.log(doubled); // [2, 4, 6]
console.log(numbers); // original unchanged

Explanation:

  • No change to original array
  • Returns a new array
  • No side effects

Pure Function Rule:

function multiply(a, b){
  return a * b;
}
  • Same input → same output
  • No external dependency

🔹 Procedural Programming

Procedural programming focuses on step-by-step instructions to solve a problem.

  • Uses variables and loops
  • Changes data directly (mutable)
  • Execution follows sequence of steps

Example:

let result = 0;

for(let i = 1; i <= 3; i++){
  result += i;
}

console.log(result); // 6

Array Example:

let numbers = [1, 2, 3];
let doubled = [];

for(let i = 0; i < numbers.length; i++){
  doubled.push(numbers[i] * 2);
}

console.log(doubled); // [2, 4, 6]

Explanation:

  • Uses loop and variables
  • Step-by-step logic
  • More control but more code

🔹 Key Differences

Functional Programming Procedural Programming
Uses pure functions Uses step-by-step instructions
No side effects Can modify data
Immutable data Mutable data
Short and declarative Long and detailed
Uses map, filter, reduce Uses loops (for, while)

🔹 Real-Life Analogy

Functional: Like using a calculator → input → output (no change inside)

Procedural: Like cooking recipe → step-by-step instructions

🔹 When to Use

  • Functional: Data transformation, React development, clean code
  • Procedural: Simple logic, algorithms, step-based problems

Key Point: Functional focuses on what to do, Procedural focuses on how to do.

11. Polyfills (Concept)

A Polyfill is a piece of code used to provide modern JavaScript features in older browsers that do not support them.

It ensures that your code works consistently across all browsers.

🔹 Simple Definition

Polyfill = Fallback code for missing features

🔹 Why Polyfills are Needed

  • Older browsers do not support modern JS features
  • Example: map(), filter(), Promise
  • Polyfills add these features manually

🔹 Example: Array.map Polyfill

if(!Array.prototype.map){
  Array.prototype.map = function(callback){
    let result = [];

    for(let i = 0; i < this.length; i++){
      result.push(callback(this[i], i));
    }

    return result;
  }
}

🔍 Explanation:

  • if(!Array.prototype.map) → checks if map() is not available
  • If missing → we define our own map()
  • this → refers to the array on which map is called
  • callback → function applied to each element
  • Loop runs through array and builds a new array

🔹 Usage Example

let numbers = [1, 2, 3];

let doubled = numbers.map(num => num * 2);

console.log(doubled); // [2, 4, 6]

Even if browser doesn't support map(), polyfill makes it work.

🔹 Another Simple Polyfill Example (Custom)

if(!String.prototype.repeat){
  String.prototype.repeat = function(n){
    let result = "";
    for(let i = 0; i < n; i++){
      result += this;
    }
    return result;
  }
}

console.log("Hi".repeat(3)); // HiHiHi

🔹 Important Rules for Polyfills

  • Always check if feature exists before adding
  • Do NOT overwrite existing functionality
  • Write clean and optimized code

🔹 Real-Life Analogy

Imagine your phone doesn’t support a new app feature 📱
You install an update or workaround → that is a polyfill

Key Point: Polyfills allow modern JavaScript code to run in older browsers.
