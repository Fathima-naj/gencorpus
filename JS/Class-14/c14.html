Asynchronous JavaScript

JavaScript is single-threaded, meaning it executes one task at a time. However, modern applications require operations that take time such as:

  • API requests
  • File reading
  • Database queries
  • Timers
  • User interactions

To handle these tasks without blocking the program, JavaScript uses asynchronous programming.

1. Synchronous JavaScript

In synchronous execution, code runs line by line. Each task must finish before the next one starts. 

console.log("Start");
console.log("Process data");
console.log("End");
Every statement waits for the previous statement to complete.

Problem with Synchronous Code

console.log("Start");
for(let i = 0; i < 1e9; i++){}
console.log("End");

This blocks execution and freezes UI.

2. Asynchronous JavaScript

console.log("Start");

setTimeout(() => {
console.log("Async Task");
}, 2000);

console.log("End");

Start
End
Async Task
setTimeout runs later, allowing other code to execute first.

3. Callbacks

function greet(name, callback){
console.log("Hello " + name);
callback();
}

Async Callback Example

function fetchData(callback){
setTimeout(() => {
console.log("Data received");
callback();
}, 2000);
}
Callback runs only after async task completes.

4. Callback Hell

setTimeout(() => {
console.log("Step 1");

setTimeout(() => {
console.log("Step 2");

setTimeout(() => {
console.log("Step 3");
}, 1000);

}, 1000);

}, 1000);
Deep nesting makes code unreadable and hard to maintain.

5. Promises

What is a Promise?

A Promise is an object that represents the eventual completion or failure of an asynchronous operation.

Example idea: "I will give you the result later (success or failure)."

Why Promises?

  • Avoid callback hell
  • Better readability
  • Improved error handling

Promise States

  • Pending → Operation is running
  • Fulfilled (Resolved) → Success
  • Rejected → Failed

Example

let promise = new Promise((resolve, reject) => {
    let success = true;

    if(success){
        resolve("Data loaded");
    } else {
        reject("Error");
    }
});

Flow:

  • Initially → Pending
  • If success → Resolved
  • If failure → Rejected

Consuming a Promise

promise
  .then((res) => {
    console.log(res);
  })
  .catch((err) => {
    console.log(err);
  });
  • .then() → Runs on success
  • .catch() → Runs on error

Real Example (API)

fetch("https://api.com/data")
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.log(err));

6. async / await

What is async / await?

Modern way to handle promises, making code look synchronous and readable.

async Keyword

async function fetchData() {
    return "Hello";
}

Always returns a Promise.

await Keyword

async function fetchData(){
    let data = await getData();
    console.log(data);
}
await pauses execution until the Promise resolves.

Example with Delay

function getData(){
    return new Promise((resolve) => {
        setTimeout(() => {
            resolve("Data received");
        }, 2000);
    });
}

async function fetchData(){
    let data = await getData();
    console.log(data);
}

fetchData();

Error Handling

async function fetchData(){
    try {
        let data = await getData();
        console.log(data);
    } catch (error) {
        console.log(error);
    }
}

Promise vs async/await

  • Promise (.then) → Chain-based
  • async/await → Cleaner & readable
  • Error handling: .catch() vs try...catch

Key Points

  • Promise handles async operations
  • resolve → success
  • reject → failure
  • async returns promise
  • await waits for result

7. JavaScript Event Loop (DEEP + VISUAL EXPLANATION)

JavaScript is single-threaded, meaning it can execute only one task at a time. But it can still handle asynchronous operations using the Event Loop.

📊 Event Loop Diagram

This diagram shows how Call Stack, Web APIs, Callback Queue, and Event Loop work together.

🧠 Core Components Explained

  • Call Stack

The Call Stack is where JavaScript executes code line by line. It follows LIFO (Last In First Out). 

function first(){
second();
}

function second(){
console.log("Hello");
}

first();

Stack Order: 

first()
second()
console.log()
  • Web APIs

Web APIs are provided by the browser (not JavaScript). They handle asynchronous tasks like:

  • setTimeout
  • fetch (API calls)
  • DOM events (click, input)
Purpose: Move time-consuming tasks OUTSIDE the call stack to avoid blocking.
  • Callback Queue (Task Queue)

After an async task completes in Web APIs, its callback function is placed in the Callback Queue.

It waits here until the Call Stack becomes empty.
  • Event Loop

The Event Loop continuously checks: 

"Is Call Stack empty?"

If YES → it moves the callback from queue → to Call Stack

Event Loop is like a manager that coordinates execution.

⚙️ Step-by-Step Execution Example

console.log("Start");

setTimeout(() => {
console.log("Async Task");
}, 2000);

console.log("End");

🔍 Internal Working

1. "Start" → goes to Call Stack → executed

2. setTimeout → sent to Web API
   Timer starts (2 sec)

3. "End" → executed immediately

4. After 2 sec → callback goes to Callback Queue

5. Event Loop checks → Call Stack empty? YES

6. Moves callback → Call Stack

7. "Async Task" executes

📌 Important Rule

Even if delay is 0ms, callback runs ONLY after Call Stack is empty. 
console.log("Start");

setTimeout(() => {
console.log("Timeout");
}, 0);

console.log("End");

Output:
Start
End
Timeout

🚀 Microtask vs Macrotask (VERY IMPORTANT)

There are TWO queues:

  • Microtask Queue → Promises (.then, async/await)
  • Macrotask Queue → setTimeout, setInterval
Microtasks ALWAYS execute before Macrotasks.

Example

console.log("Start");

setTimeout(() => console.log("Timeout"), 0);

Promise.resolve().then(() => console.log("Promise"));

console.log("End");

Output

Start
End
Promise
Timeout

🧩 Real Understanding Flow

1. Execute all synchronous code (Call Stack)

2. Check Microtask Queue → execute all (Promises)

3. Then take one Macrotask (setTimeout)

4. Repeat cycle
This cycle keeps running → that's the Event Loop.

🎯 Real-Life Analogy

Call Stack = Chef 👨‍🍳
Web API = Kitchen Staff 👩‍🍳
Callback Queue = Ready Orders Table 🍽️
Event Loop = Waiter 🧑‍🍽️

Chef cooks main dishes. Time-consuming tasks are given to staff. When ready → waiter brings them back to chef.
