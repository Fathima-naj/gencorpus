React Introduction

1. What is React?

React is a JavaScript library used to build fast, interactive user interfaces.

It helps developers create applications where the UI changes dynamically without reloading the page.

1. Why do we need React if we already have HTML, CSS, JavaScript?

we can build websites using HTML, CSS, and JavaScript alone. But:

  • Managing UI becomes very complex in large applications
  • Too much manual DOM manipulation
  • Code becomes messy and hard to maintain
  • Performance becomes slower

React solves this by:

  • Automatically updating UI
  • Using reusable components
  • Making code clean and structured

2. What is a Library?

A library is a collection of pre-written code that helps you perform tasks easily.

👉 Example:

  • You write everything manually → Normal JS
  • You use ready-made functions → Library (React)

Important:

  • Library = You control the flow

3. What does “Dynamic UI” mean?

Dynamic UI means the content changes automatically based on data without refreshing the page.

👉 Example:

  • Click Like ❤️ → count increases instantly
  • Add to cart → cart updates immediately

Without React: You must manually update DOM using JavaScript.

With React: UI updates automatically when data changes.

Key Points:

  • Developed by Facebook
  • Used for building modern web apps
  • Focuses only on UI (View layer)
  • Works with other libraries for full app (like Redux, Router)

Real Life Example:

When you like a post on Instagram ❤️ → count increases instantly without page reload → That is React behavior.

2. Why React?

Problems before React:

  • Too much DOM manipulation
  • Code becomes messy in large apps
  • Slow performance

React Solutions:

  • Component Reusability → Write once, use many times
  • Fast Rendering → Virtual DOM
  • Maintainability → Clean structure
  • Scalability → Easy for large projects

3. SPA (Single Page Application)

SPA means the application loads only one HTML page and updates content dynamically.

Traditional Website (MPA):

  • Every click → new page request
  • Full reload happens
  • Slower experience

React SPA:

  • Page loads once
  • Only content updates
  • No reload
  • Faster and smoother UX

SPA vs MPA Flow

MPA → Click → Request → Server → New Page → Reload ❌

SPA → Click → JS updates UI → No Reload ✅

4. React Features

4.1 Declarative UI

You describe what UI should look like, React handles updates.

const isLogin = true;

return (
  <div>
    {isLogin ? <h1>Welcome</h1> : <h1>Login</h1>}
  </div>
);

👉 When isLogin changes → UI updates automatically.

4.2 Component-Based Architecture

UI is divided into small reusable parts called components.

function Button(){
  return <button>Click</button>
}

👉 Benefits:

  • Reusable
  • Easy debugging
  • Clean code

4.3 Virtual DOM

The Virtual DOM is a lightweight (in-memory) copy of the real DOM. React uses it to make UI updates faster and more efficient.

❓ Why Virtual DOM is Needed?

  • Updating the real DOM is slow (browser operation is expensive)
  • If we update the whole DOM every time → performance becomes poor
  • React solves this using Virtual DOM

Simple Understanding:

Instead of updating the real DOM directly, React:

  • Creates a copy (Virtual DOM)
  • Finds what exactly changed
  • Updates only that part in real DOM

Step-by-step Working:

  1. User action happens (click, input, etc.)
  2. State or data changes
  3. React creates a new Virtual DOM
  4. Compares it with the previous Virtual DOM (Diffing)
  5. Finds the difference (changed elements only)
  6. Updates only those changes in the real DOM

💡 Example:

Suppose you have a list of 100 items and you update only 1 item:

  • Normal JS → may re-render all 100 items ❌
  • React → updates only 1 changed item ✅

🚀 Benefits:

  • Faster UI updates
  • Better performance
  • Smooth user experience
  • Less direct DOM manipulation

Virtual DOM Flow

User Action → State Change → New Virtual DOM

Old Virtual DOM vs New Virtual DOM (Diffing)

Find Changes → Update Only That Part in Real DOM → Fast UI 🚀

5. JSX (JavaScript XML)

JSX allows writing HTML inside JavaScript.

const element = <h1>Hello</h1>;

Rules:

  • Must return single parent element
  • Use className instead of class
  • Close all tags

7. Folder Structure

In a React project, files are organized to make development easy and scalable.

my-project/
 ├── node_modules/      → installed packages (React, etc.)
 ├── public/            → static files (icons, images)
 ├── src/               → main development folder 🔥
 ├── index.html         → main HTML file
 ├── package.json       → project details & dependencies
 ├── vite.config.js     → Vite configuration

Important Folders & Files:

  • node_modules/ → Contains all installed libraries (auto-generated, don’t edit)
  • public/ → Static files like images, icons
  • index.html → Root HTML file where React loads
  • package.json → Stores project info and dependencies
  • vite.config.js → Configuration for Vite build tool

Inside src/ 

src/
 ├── assets/        → images, logos
 ├── App.css        → styles for App
 ├── App.jsx        → main component
 ├── index.css      → global styles
 └── main.jsx       → entry point
  • assets/ → Stores images and files
  • App.jsx → Root component (UI starts here)
  • App.css → Styling for App component
  • index.css → Global styling for entire app
  • main.jsx → Entry point that connects React to HTML

Application Flow:

index.html → main.jsx → App.jsx → UI Render

Simple Understanding:

  • index.html → Base (root div)
  • main.jsx → Starts React
  • App.jsx → Displays UI
