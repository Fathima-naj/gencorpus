Events & Forms Basics

1. Event Handling in React

Event handling in React is similar to HTML, but uses camelCase and functions.

  • HTML → onclick
  • React → onClick
function App(){ function handleClick(){ alert("Button Clicked"); } return ( <button onClick={handleClick}>Click Me</button> ); }

Important: Always pass a function, not function call.

// ❌ Wrong onClick={handleClick()} // ✅ Correct onClick={handleClick}

2. Synthetic Events

In React, events are not handled directly using browser events. Instead, React creates its own event system called Synthetic Events.

A Synthetic Event is a wrapper around the browser’s native event. It behaves the same way but works consistently across all browsers.

  • Provides the same behavior in all browsers (Chrome, Firefox, etc.)
  • Fixes browser differences automatically
  • Improves performance by managing events efficiently

Simple Idea:

Instead of using the browser event directly, React gives you a “standard version” of that event.

function handleClick(e){ console.log(e); // Synthetic Event (React event object) }

👉 Here, e is not a normal DOM event. It is a Synthetic Event created by React.

Common Properties you will use:

  • e.target → the element that triggered the event
  • e.target.value → value of input field
  • e.preventDefault() → stops default behavior (like form reload)
function handleChange(e){ console.log(e.target.value); // input value }

Real-life Understanding:

Different browsers handle events slightly differently. React solves this by creating Synthetic Events so developers can write code once and it works the same everywhere.

Important Note:

  • You use Synthetic Events in all React events like onClick, onChange, onSubmit
  • You don’t need to worry about browser differences

3. Handling Inputs

React uses onChange to handle input changes.

const [name, setName] = useState(""); <input type="text" value={name} onChange={(e) => setName(e.target.value)} />
  • value → controlled by state
  • onChange → updates state

4. onChange Event

Triggered whenever input value changes.

function handleChange(e){ setName(e.target.value); }

Used for text, checkbox, select, etc.

5. onSubmit Event

Used to handle form submission.

function handleSubmit(e){ e.preventDefault(); // stop page reload console.log("Form Submitted"); }
<button type="submit">Submit</button>
  • Forms reload page by default
  • use e.preventDefault() to stop it

6. Controlled Components

Controlled components are inputs controlled by React state.

const [email, setEmail] = useState(""); <input type="email" value={email} onChange={(e) => setEmail(e.target.value)} />
  • React controls input value
  • Single source of truth = state

7. Uncontrolled Components

Uncontrolled components use DOM directly (no state).

<input type="text" />
  • Value is stored in DOM
  • Less control

Using ref (advanced):

const inputRef = useRef(); < input ref={inputRef} />

8. useRef

useRef is a React Hook used to create a reference that persists across renders.

import { useRef } from "react"; const inputRef = useRef();
  • Stores value inside .current
  • Does NOT trigger re-render
  • Value persists across renders
Doubt Clarification:
useRef does NOT reset on re-render.
Value remains same unless manually changed.

Accessing DOM Element

const inputRef = useRef(); function handleClick(){ inputRef.current.focus(); }
Explanation:
inputRef.current points to actual DOM element

Storing Value Without Re-render

const countRef = useRef(0); function handleClick(){ countRef.current++; console.log(countRef.current); }
Important:
Updating useRef value does NOT update UI automatically

useRef vs useState

  • useState → triggers re-render
  • useRef → does NOT trigger re-render
Key Understanding:
useRef = store value silently
useState = store value and update UI

When to Use useRef?

  • Access DOM elements (focus, scroll)
  • Store previous values
  • Store mutable data without re-render

9. Re-render

Doubt Clarification:
Re-render = component runs again when state/props change
UI updates but page does NOT reload
Important Difference:
useState → triggers re-render
useRef → does NOT trigger re-render

8. Controlled vs Uncontrolled

  • Controlled → React manages data ✅
  • Uncontrolled → DOM manages data ❌

Recommendation: Always use controlled components in React.
