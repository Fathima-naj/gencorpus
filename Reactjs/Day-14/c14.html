React Context API

Context API is a built-in feature in React that allows you to share data globally across components without passing props manually through every level.

  • Helps avoid prop drilling
  • Used for global data like theme, user authentication, language
  • Improves code readability and maintainability
Real World Example: Dark/Light mode, Logged-in user info, App language settings

1. What is Context?

Context provides a way to share values like state, functions, or objects between components without explicitly passing props through each level of the component tree.

It acts like a global storage inside your React app.

// Without Context App → Parent → Child → GrandChild ❌ // With Context App → Context → Any Component ✅
  • Data becomes accessible anywhere inside the Provider
  • Reduces unnecessary prop passing

2. Prop Drilling Problem

Prop drilling occurs when you pass data from a top-level component to deeply nested components through multiple intermediate components.

function App(){ return <Parent name="Fathima" /> } function Parent(props){ return <Child name={props.name} /> } function Child(props){ return <GrandChild name={props.name} /> }
  • Intermediate components don’t need the data but still pass it
  • Leads to messy and hard-to-maintain code
  • Increases complexity in large applications
👉 Context API solves this by providing direct access to data

3. Creating Context

Context is created using the createContext() function. It returns a Context object that contains two main components:

  • Provider → used to provide data
  • Consumer → used to access data
import { createContext } from "react"; export const MyContext = createContext();

You can also pass a default value while creating context. This value is used when a component tries to access context outside a Provider.

export const MyContext = createContext("Guest User");
  • Default value acts as fallback
  • Useful for testing or avoiding undefined errors
👉 Important: Default value is used ONLY if no Provider is found above the component

🔍 Behind the Scenes

React internally keeps track of the nearest Provider above a component. When a component calls useContext, it reads data from the closest Provider.

// If multiple providers exist <MyContext.Provider value="A"> <MyContext.Provider value="B"> <Child /> </MyContext.Provider> </MyContext.Provider> // Child will get "B" (nearest provider)

4. Provider

The Provider is used to wrap components and make data available to all its child components.

import { MyContext } from "./MyContext"; function App(){ return ( <MyContext.Provider value={{name: "Fathima"}}> <Home /> </MyContext.Provider> ); }
  • value → data shared globally
  • All child components can access this data
  • Works for deeply nested components

📦 Passing Multiple Values

You can pass multiple values using an object.

value={{ name: "Fathima", age: 21, isLoggedIn: true }}

Then access them using:

const { name, age } = useContext(MyContext);

5. Consumer (Old Method)

Consumer is the older way to access context values.

<MyContext.Consumer> {(data) => <p>{data.name}</p>} </MyContext.Consumer>
  • Uses a function as a child
  • Less readable compared to hooks
👉 Rarely used now, replaced by useContext

6. useContext Hook (Modern Way)

The useContext hook is the modern and easiest way to access context values.

import { useContext } from "react"; import { MyContext } from "./MyContext"; function Home(){ const data = useContext(MyContext); return <p>{data.name}</p>; }
  • Cleaner syntax
  • Direct access to context value
  • Works inside functional components

7. When to Use Context?

  • Authentication (user login data)
  • Theme (dark/light mode)
  • Language settings
  • Global app settings
👉 Avoid using Context for frequently changing large data (can affect performance)

Summary

  • Context API → global state management
  • Avoids prop drilling
  • Provider → supplies data
  • useContext → consumes data
  • Best for small to medium global state
