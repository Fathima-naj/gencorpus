JSX (JavaScript XML)

1. What is JSX?

JSX (JavaScript XML) is a syntax used in React to write HTML-like code inside JavaScript.

It makes UI code easier to read and write.

JSX is not real HTML. It gets converted into JavaScript (React.createElement) behind the scenes.

const element = <h1>Hello World</h1>;

Converted to:

React.createElement("h1", null, "Hello World");

How JSX Works (Babel & React.createElement)

JSX does NOT work directly in the browser.

Browsers understand only JavaScript, not JSX.

So JSX must be converted into normal JavaScript.

Step 1: Babel (Compiler)

Babel is a JavaScript compiler that converts JSX into JavaScript.

It transforms JSX into React.createElement() calls.

const element = <h1>Hello</h1>;

Babel converts it into:

const element = React.createElement("h1", null, "Hello");

Step 2: React.createElement()

This function creates a React Element (Virtual DOM object).

Syntax:

React.createElement(type, props, children)
  • type → HTML tag or component
  • props → attributes (className, id, etc.)
  • children → content inside element

Example Breakdown

const element = (
  <h1 className="title">
    Hello World
  </h1>
);

Converted to:

const element = React.createElement(
  "h1",
  { className: "title" },
  "Hello World"
);

Nested JSX Example

const element = (
  <div>
    <h1>Hello</h1>
    <p>Welcome</p>
  </div>
);

Converted to:

const element = React.createElement(
  "div",
  null,
  React.createElement("h1", null, "Hello"),
  React.createElement("p", null, "Welcome")
);

Final Flow

JSX → Babel → React.createElement() → Virtual DOM → Real DOM

Key Points

  • JSX is just syntactic sugar
  • Babel compiles JSX into JavaScript
  • React.createElement creates Virtual DOM
  • React updates only changed parts in Real DOM

2. JSX Rules & Syntax

  • JSX must return a single parent element
  • Every tag must be closed
  • Use camelCase for attributes
  • Use className instead of class
  • Use { } to write JavaScript inside JSX

Example:

function App(){
  return (
    <div>
      <h1>Hello</h1>
      <p>Welcome</p>
    </div>
  );
}

3. JSX vs HTML Differences

HTML JSX
class className
onclick onClick
Can have multiple root elements Only one root element
Attributes are strings Attributes can use JS ( { } )

Example:

<!-- HTML -->
<input class="box" />

<!-- JSX -->
<input className="box" />

4. Embedding Expressions in JSX

You can use JavaScript inside JSX using { }.

Types of expressions:

  • Variables
  • Math operations
  • Functions
  • Conditions
const name = "Fathima";

<h1>Hello {name}</h1>

Examples:

<p>2 + 2 = {2 + 2}</p>

<p>{true ? "Yes" : "No"}</p>

function greet(){
  return "Good Morning";
}

<h1>{greet()}</h1>

Important Notes:

  • Expressions return a value
  • Statements (if, for) cannot be directly used

5. JSX If Statements (Conditional Rendering)

JSX does NOT allow direct if statements inside return.

❌ Wrong:

<h1>
  if(true){
    Hello
  }
</h1>

✅ Correct Methods:

1. Ternary Operator

<h1>
  {isLoggedIn ? "Welcome" : "Please Login"}
</h1>

2. Logical AND (&&)

{isAdmin && <p>Admin Panel</p>}

3. If outside JSX

let message;

if(isLoggedIn){
  message = "Welcome";
}else{
  message = "Login";
}

<h1>{message}</h1>

6. JSX with Attributes

Attributes in JSX are written using camelCase and can use JavaScript.

const url = "https://google.com";

<a href={url}>Go to Google</a>

Inline Styling:

<h1 style={{color: "red", fontSize: "20px"}}>
  Hello
</h1>

Note: Style uses object (double curly braces)

a) class → className

In JSX, class is replaced by className.

Reason: "class" is a reserved keyword in JavaScript.

<div className="container">Hello</div>

b) CamelCase Attributes

JSX uses camelCase for attributes.

onclick  → onClick
tabindex → tabIndex

c) Event Attributes

Events are written in camelCase and use functions.

function clickMe(){
  alert("Clicked");
}

<button onClick={clickMe}>Click</button>

d) Boolean Attributes

Boolean values are written inside {}.

<input disabled={true} />
<input disabled={false} />

Shortcut:

<input disabled />

e) Style Attribute

Style is written as a JavaScript object.

<h1 style={{color:"red", fontSize:"20px"}}>
  Hello
</h1>

Rules:

  • Use camelCase (fontSize)
  • Value must be string or number

7. Multi-line JSX Code

JSX written in multiple lines must be wrapped inside parentheses ( ).

function App(){
  return (
    <div>
      <h1>Hello</h1>
      <p>Welcome</p>
    </div>
  );
}

Why?

  • Improves readability
  • Prevents JavaScript errors
  • Required when JSX spans multiple lines

8. One Top-Level Element Rule

JSX must have only one parent element.

❌ Wrong:

return (
  <h1>Hello</h1>
  <p>World</p>
);

✅ Correct:

return (
  <div>
    <h1>Hello</h1>
    <p>World</p>
  </div>
);

9. Fragment Usage

Fragments allow grouping multiple elements without adding extra DOM nodes.

Why? Avoid unnecessary divs

import React from "react";

function App(){
  return (
    <>
      <h1>Title</h1>
      <p>Paragraph</p>
    </>
  );
}

Alternative:

<React.Fragment>
  <h1>Hello</h1>
</React.Fragment>

10. Comments in JSX

Comments inside JSX must be written using {/* comment */}.

return (
  <div>
    {/* This is a comment */}
    <h1>Hello</h1>
  </div>
);

Outside JSX:

// Normal JS comment

🛠 Practice: Convert HTML UI into JSX

HTML:

<div class="card">
  <img src="image.jpg" alt="img">
  <h2>Product</h2>
  <button onclick="buy()">Buy</button>
</div>

JSX:

function Card(){

  function buy(){
    alert("Purchased");
  }

  return (
    <div className="card">
      <img src="image.jpg" alt="img" />
      <h2>Product</h2>
      <button onClick={buy}>Buy</button>
    </div>
  );
}
