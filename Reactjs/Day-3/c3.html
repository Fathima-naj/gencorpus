React Components

1. What are Components?

Components are the core building blocks of a React application.

React follows a component-based architecture, where the UI is divided into small independent parts.

Instead of updating the whole page like traditional DOM manipulation, React updates only specific components. This makes applications fast and efficient.

  • Reusability – Same component can be used multiple times
  • Maintainability – Fix one component, changes reflect everywhere
  • Scalability – Large apps can be built easily
  • Separation of concerns – Each component handles its own logic

2. Functional Components

A functional component is simply a JavaScript function that returns JSX.

JSX is not HTML — it is converted into React.createElement() internally. 

function Header(){
  return <h1>Welcome</h1>
}

const Header = () => <h1>Welcome</h1>;

🔹 Rules

  • Must start with capital letter
  • Must return JSX
  • Must have one parent element

❗ Why One Parent?

React can only return one object. JSX compiles into one JavaScript object.

3. Exporting Components

Export is used to share components between files.

React apps are modular. Each component is in a separate file. Export helps in code organization and reusability across files.

🔹 Default Export

// Header.jsx
function Header(){
  return <h1>Header</h1>
}

export default Header;
  • Only one default export per file
  • Can import with any name
import MyHeader from "./Header";

🔹 Named Export

// Named Export
export const Header = () => <h1>Header</h1>;
  • Multiple exports allowed
  • Name must match exactly
import { Header } from "./Header";

💡 When to Use?

  • Default → when one main component
  • Named → when multiple utilities/components

4. Importing Components

Import is used to use components from other files.

Import connects different files, allowing React to build a component tree. 

import Header from "./Header";

import { Header } from "./Header";

function App(){
  return (
    <div>
      <Header />
    </div>
  )
}

⚠️ Common Errors

  • Wrong file path
  • Default vs Named confusion
  • Missing export

5. Component Reusability

Reusability means writing once and using multiple times.

React avoids duplication. Instead of copying code, you reuse components, which improves performance and reduces bugs. 

function Card(){
  return <div>Product Card</div>
}

function App(){
  return (
    <div>
      <Card />
      <Card />
      <Card />
    </div>
  )
}

6. Component Composition

Composition means combining smaller components to build bigger UI.

React follows composition over inheritance. Instead of extending classes, we combine components. 

function Header(){
  return <h1>Header</h1>
}

function Footer(){
  return <h1>Footer</h1>
}

function App(){
  return (
    <div>
      <Header />
      <p>Main Content</p>
      <Footer />
    </div>
  )
}

7. Complete Example

This structure represents a real React app where each UI part is modular. React combines them into a component tree. 

// Header.jsx
const Header = () => {
  return (
    <header>
      <h1>My Website</h1>
    </header>
  )
}
export default Header;

// Footer.jsx
const Footer = () => {
  return (
    <footer>
      <p>© 2026 My Website</p>
    </footer>
  )
}
export default Footer;

// Card.jsx
const Card = () => {
  return (
    <div className="card">
      <h3>Product Name</h3>
      <p>Price: ₹500</p>
    </div>
  )
}
export default Card;

// App.jsx
import Header from "./Header";
import Footer from "./Footer";
import Card from "./Card";

function App(){
  return (
    <div>
      <Header />
      <Card />
      <Card />
      <Card />
      <Footer />
    </div>
  )
}

export default App;

Summary

  • Components = reusable UI blocks
  • Functional components return JSX
  • Export → share components
  • Import → use components
  • Reusability avoids duplication
  • Composition builds complex UI
  • React uses component tree structure
